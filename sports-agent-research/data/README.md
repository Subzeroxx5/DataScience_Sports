# Data

This directory holds controlled, **synthetic** data used for experiments. No
record in this directory represents a live or historical real-world
sportsbook price. All odds, teams, games, and probabilities are fabricated
for the purpose of this research prototype and must never be presented as
real betting information.

## Files

| File | Purpose |
|---|---|
| `current_odds.json` | Flat ledger of current, structured sportsbook prices. Read by dataset loaders (`src/evaluation/dataset.py`) and, later, by Milestone 5 sportsbook tools. |
| `historical_odds.json` | Flat ledger of stale/superseded prices for the 3 freshness scenarios. Not used to build `TestScenario` objects — reserved for Milestone 6 RAG document ingestion, so RAG can be given outdated odds while tools see current ones. |
| `test_scenarios.json` | Scenario definitions: game, market, and the experiment's reference probability. References `current_odds.json` by `game_id` rather than duplicating odds data. |
| `ground_truth.json` | Deterministically generated by `python -m src.evaluation.ground_truth` from `test_scenarios.json` + `current_odds.json` via `src/calculations/odds_math.py`. Never hand-edited. |
| `rag_documents/` | Source documents for the vector database (added in Milestone 6). |

## Sportsbooks

A fixed, controlled set of four sportsbook names is used throughout:

```text
DraftKings
FanDuel
BetMGM
Caesars
```

These are used only as controlled data-source labels for this research
prototype, not as an endorsement or representation of real sportsbook
pricing.

## Scenario Structure

Each entry in `test_scenarios.json` has:

```text
scenario_id                    unique identifier, e.g. "S001"
category                       descriptive tags for humans only — dataset
                                and ground-truth tests verify coverage from
                                the actual computed data, not these tags
game                            game_id, home_team, away_team, start_time, sport
market                          market_type (moneyline/spread/total), selected_outcome, line
estimated_true_probability      see below
current_odds_version             version tag copied into ground truth for
                                traceability (e.g. "v1")
```

The odds themselves are **not** embedded in `test_scenarios.json`; they are
looked up from `current_odds.json` by `game_id` when a `TestScenario`
Pydantic object is built (`src/evaluation/dataset.py::build_test_scenario`).

## Estimated True Probability

`estimated_true_probability` is **not** a claim about the real-world
probability of any outcome. It is the experiment's assumed reference
probability, used only to calculate deterministic ground truth (implied
probability, expected value, positive/negative EV classification) via
`src/calculations/odds_math.py`. Treat it as a controlled experimental
input, not a forecast.

## Current vs. Stale Records

`current_odds.json` records always have `"is_current": true`.
`historical_odds.json` records always have `"is_current": false` and an
earlier `"timestamp"` than their current counterpart, plus `"version":
"v0"` (vs. `"v1"` for current). Three scenarios (`S009`, `S010`, `S011`)
each have exactly one sportsbook with a stale counterpart record, so later
architecture comparisons can test whether an agent uses the current price
or an intentionally outdated one.

## Missing-Data Policy

A sportsbook that does not offer a line for a scenario is **omitted
entirely** from `current_odds.json` for that `game_id` — it never appears
with `american_odds: 0`. `american_odds = 0` remains invalid at the
`SportsbookOdds` model level (Milestone 2) and is never used to represent
"no data." Ground truth's `expected_sportsbooks` field reflects only the
sportsbooks actually present, so completeness can be measured against it
(`S008` is the missing-data example: FanDuel is absent).

## Tie Policy

When multiple sportsbooks offer equally favorable odds for the best price
(same implied probability, e.g. two books both at `+125`), ground truth
preserves **all** of them in `expected_best_sportsbooks` (sorted
alphabetically), not just one. `expected_best_sportsbook` (singular, kept
for Milestone 2 backward compatibility) is set to the first name in that
list. Evaluation code should treat any sportsbook in
`expected_best_sportsbooks` as a correct best-line answer. `S007` is the
tie example (`DraftKings` and `FanDuel` both at `+125`).

## Ground Truth Generation

Ground truth is produced only by deterministic Python calculations — never
by an LLM, RAG, or a hard-coded expected value. Regenerate it with:

```bash
python -m src.evaluation.ground_truth
```

This reads `test_scenarios.json` + `current_odds.json`, computes best odds,
implied probability, expected value, and positive/negative EV classification
via `src/calculations/odds_math.py`, and writes a sorted, deterministic
`ground_truth.json`. Running it twice against unchanged source data produces
a byte-identical file.

## Market Type Scope

`S012` (spread) and `S013` (total) exist to exercise the `Market` schema
across all supported market types, and ground truth is still computed for
them using the same generic American-odds math. However, they are marked
`schema_validation_only` in `category`: the initial experiment's EV
comparison across architectures is expected to focus on moneyline
scenarios, where the probability interpretation is least ambiguous.
