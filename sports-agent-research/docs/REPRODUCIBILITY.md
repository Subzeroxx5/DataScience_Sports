# Reproducibility Guide

End-to-end workflow for reproducing this project's controlled benchmark,
architectures, dashboard, and final research dataset/analysis. This
document describes commands only — it never embeds secrets (API keys,
tokens); see step 4 for how credentials are supplied.

## 1. Environment Setup

Requires Python 3.11+ (developed/tested against Python 3.13).

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

`requirements.txt` includes: `pydantic`, `pytest`, `python-dotenv`, `numpy`,
`sentence-transformers`, `faiss-cpu`, `anthropic`, `httpx`, `streamlit`,
`pandas`, `scipy`, `matplotlib`.

## 2. Controlled Benchmark Generation

The controlled sportsbook benchmark and its deterministic ground truth are
already checked into `data/`, but can be regenerated byte-identically from
the same source data at any time:

```bash
python -m src.evaluation.ground_truth          # writes data/ground_truth.json
python -m src.evaluation.quant_ground_truth    # writes data/quant_ground_truth.json
```

Both are pure functions of `data/test_scenarios.json` and
`data/current_odds.json` — no LLM, no randomness, no wall-clock dependence.
Running either command repeatedly against unchanged source data produces a
byte-identical file.

## 3. RAG Corpus / Index Construction

```bash
python -m src.rag.build_corpus   # writes data/rag_documents/corpus.jsonl
python -m src.rag.build_index    # writes data/rag_index/{index.faiss,metadata.json,config.json}
```

The corpus generator never includes ground-truth answers (enforced by
`tests/test_rag_corpus.py`'s leakage scan). The index build embeds only
`RagDocument.content` via `sentence-transformers/all-MiniLM-L6-v2` and
builds an exact FAISS inner-product index — deterministic given the corpus
and embedding model.

## 4. Ollama Setup (Local Real-LLM Backend)

The final experiment uses a locally hosted model via
[Ollama](https://ollama.com) — no API key required.

```bash
brew install ollama                  # macOS; see ollama.com for other platforms
brew services start ollama           # or: ollama serve
ollama pull llama3.1:8b              # the exact model used for the final experiment
```

Verify the server is reachable and the model is present:

```bash
curl -s http://localhost:11434/api/version
ollama list
```

The Anthropic API (`AnthropicLLMClient`) remains available as the default
provider for architectures/tests predating the local-provider checkpoint —
it requires `ANTHROPIC_API_KEY` set in the environment (e.g. via a local
`.env` file, never committed; see `.env.example`). It is **not** required
for MOCK mode or for reproducing the final REAL experiment, which used
Ollama exclusively.

## 5. Exact Final Model

The final experiment's configuration is frozen in
`experiments/final_experiment.json`:

| Setting | Value |
|---|---|
| `llm_provider` | `ollama` |
| `model_name` | `llama3.1:8b` |
| `temperature` | `0.0` |
| `rag_top_k` | `5` |
| `max_tool_iterations` | `6` |
| `embedding_model` | `sentence-transformers/all-MiniLM-L6-v2` |

Provider selection is configuration-driven
(`ExperimentConfig.llm_provider`), never architecture-specific — every
architecture (RAG/TOOL/HYBRID) receives the identical provider and model
for a given configuration.

## 6. Test Suite

```bash
pytest -q
```

The full automated suite (1097+ tests as of Milestone 15) never requires a
running Ollama server, an Anthropic API key, or any real network access —
it uses deterministic fake LLM clients throughout. Run this before and
after any change, per project convention (`CLAUDE.md`).

## 7. Experiment Runner

Two distinct execution modes exist — **do not confuse them**:

### MOCK mode (infrastructure validation only)

```bash
python -m src.experiments.runner --mode mock --repetitions 2 \
    --scenario-ids S001,S007,S008 --experiment-id my-mock-test
```

Drives the real architecture pipelines (retrieval, tool calls, source
reconciliation) but with the LLM decision layer replaced by deterministic
fake policies — no API cost, byte-for-byte reproducible (excluding
timestamps/latencies), and explicitly labeled "MOCK — INFRASTRUCTURE
VALIDATION ONLY" wherever its output appears (CLI, dashboard). **Never**
presented as a research finding.

### REAL mode (the final experiment)

```bash
python experiments/run_final_experiment.py --config experiments/final_experiment.json
```

This is the exact command that produced the frozen final dataset at
`results/experiments/final_v1/`. It runs a full preflight (test suite,
ground-truth reproducibility check, RAG/tool smoke checks, hybrid-policy
smoke check, real-inference connectivity probe) before making any real
inference call, and refuses to proceed if the frozen config's
`execution_mode` is not `real` or if the configured provider is
unreachable. **Re-running this command against `results/experiments/final_v1/`
will refuse** (duplicate-experiment protection) unless you either delete
that directory (irreversible — do not do this to the frozen final dataset)
or point `--config` at a new configuration with a different
`experiment_id`.

A lower-level equivalent for ad hoc real-mode runs (not the frozen final
experiment) is also available:

```bash
python -m src.experiments.runner --mode real --config <path-to-config.json>
```

## 8. Dataset Validation

Already run automatically as part of both experiment paths above, but can
be re-checked independently at any time without re-running anything:

```bash
python -c "
from src.analysis.loading import load_final_dataset
d = load_final_dataset('results/experiments/final_v1')
print('valid:', d.validation_report.dataset_valid)
"
```

This revalidates run counts, duplicate/missing keys, scenario/architecture
coverage, raw-result schema, ground-truth/architecture isolation, and the
9-way controlled-artifact fingerprint comparison — read-only, never
modifies `raw_results.jsonl`, `config.json`, or `manifest.json`.

## 9. Final Statistical Analysis

```bash
python -m src.analysis.final_analysis --experiment-dir results/experiments/final_v1
```

Read-only against the frozen dataset. Writes machine-readable outputs,
figures, and `findings.md` to `results/experiments/final_v1/analysis/` —
never overwrites the raw experiment files. Re-running this command
regenerates the same `analysis/` outputs from the same unchanged raw data
(descriptive statistics, confidence intervals, and test statistics are
deterministic given the frozen dataset; only wall-clock-independent values
are used).

## 10. Dashboard Launch

```bash
streamlit run dashboard/app.py
```

Two modes, selectable in the sidebar:

- **Demo** — pick one scenario and one architecture from the controlled
  scenario manifest, then click "Run Analysis" to execute it live (via the
  same `create_agent`/`build_llm_client` factory the experiment runner
  uses). Supports both MOCK and REAL execution mode; REAL requires Ollama
  (or Anthropic credentials, per the configured provider) to be reachable
  and fails clearly, without crashing, if it is not.
- **Research Comparison** — loads a previously generated experiment
  directory (e.g. `results/experiments/final_v1/`) read-only and
  visualizes architecture summaries, comparison charts, scenario
  drill-down, failure analysis, and hybrid conflict analysis. A MOCK
  experiment is always labeled "MOCK — INFRASTRUCTURE VALIDATION ONLY" in
  the UI; it is never presented as a research finding.

## Secrets

- `ANTHROPIC_API_KEY` (only needed for the Anthropic provider) is read from
  the environment by the `anthropic` SDK directly — never logged, printed,
  or written to any persisted experiment artifact (verified by a dedicated
  test asserting no experiment metadata file contains the string
  `ANTHROPIC_API_KEY` or `sk-ant-`).
- Ollama requires no credentials — it is an unauthenticated local server.
- Copy `.env.example` to `.env` and fill in real values locally; `.env` is
  git-ignored and must never be committed.
